A photography portfolio website for £0 a month

This website costs me nothing a month to host. No Squarespace, no Wix, no Shopify plan. It runs on GitHub Pages, on my own domain, and the only bill is the domain itself. Here's how it's set up, what it can and can't do, and the catch.

1. The catch first

There's no drag-and-drop editor. The site is plain files: one small script turns my photos and text into web pages. I'm a software engineer, so that suits me, and I build and change it with Claude, an AI assistant, which writes and checks the code with me. If you never want to see a file or a terminal, a paid site builder is the easier road. If you're happy to follow steps, this saves you £15 to £30 a month.

2. What it costs

  • Hosting: £0. GitHub Pages is free for public repositories.
  • Domain: what your registrar charges each year. Mine is on Cloudflare, which sells domains at cost.
  • Security certificate (the padlock): £0, included.
  • Analytics: £0. Cloudflare Web Analytics counts visits without cookies.

3. How it works

  1. Your originals stay on your computer. Full-size photos never go online.
  2. A build script makes web-size copies of each photo and writes the pages as plain HTML.
  3. GitHub keeps the finished site. Every time you push a change, it checks the pages and publishes them.
  4. Your domain points at GitHub Pages, so visitors see yourname.com, not a GitHub address.

4. The steps

  1. A GitHub account. Sign up with your business email and turn on two-factor sign-in. Keep your personal email private in GitHub's settings.
  2. A repository named after your domain, set to public. It holds the build script, your text, and the built site in a folder called site.
  3. Choose your pages. Mine: the work, the book, guides, about, terms. Keep it to your best 12 to 30 photos to start.
  4. Write the build script. One Python script, no framework: it reads a list of photos and their descriptions, makes the image sizes, and writes each page. This is the part I built with Claude.
  5. Preview on your own computer before anything goes online.
  6. Turn on Pages: repository Settings, Pages, deploy with GitHub Actions. A short workflow file checks the build and publishes the site folder whenever you push to the main branch.
  7. Verify the domain first in your GitHub account settings (Settings, Pages, Add a domain). GitHub gives you one TXT record to add in Cloudflare. This stops anyone else claiming your domain for their own Pages site.
  8. Connect your domain. In Pages settings, add your domain. In Cloudflare DNS, add GitHub's four A records and four AAAA records for the root, and a CNAME for www pointing to yourname.github.io. Then tick Enforce HTTPS.

GitHub's addresses change rarely, but check their current list in the GitHub Pages docs before you add them.

5. Photos that load fast and stay yours

  • Three sizes of every photo (around 640, 1200 and 2000 pixels wide), so phones don't download a huge file. The largest is too small for a good print, which protects your work.
  • Two formats: AVIF, which is small, with JPEG as a fallback for older browsers.
  • Location data removed. Re-saving the photos drops the GPS and camera serial number from the originals.
  • Your name added back: creator, credit and copyright written into each web JPEG.
  • Proper descriptions (alt text) on every photo, which helps people using screen readers and helps Google understand the page.

6. What it can't do

  • No shop on GitHub itself. GitHub Pages isn't for running an online business. For sales I link out: Gumroad for downloads, Stripe for the printed book.
  • No contact forms or logins on their own. I use an email link, and a separate service (Sender) for the newsletter sign-up.
  • Size limits. The published site can be up to 1 GB, with a soft limit of 100 GB of traffic a month. A portfolio is far under both.
  • Public code. On the free plan the repository is public, so never put anything private in it: no client details, no bank details, no full-size originals.
